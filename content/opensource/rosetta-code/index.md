# Overview

> [!TIP]
> **Repository:** [github.com/seucra/rust-rosetta ↗](https://github.com/seucra/rust-rosetta)

Rust Rosetta Code represents one of my earliest deliberate attempts to contribute to open source while learning Rust.

Rather than treating open source as something to attempt only after becoming highly experienced, I wanted to become comfortable reading existing codebases, understanding contribution workflows and improving code through practical participation.

Although these contributions were relatively small, they marked an important transition from learning privately to participating publicly.

---

# Motivation

After beginning Rust, I realized that writing personal projects alone would not expose me to how real software communities operate.

Rosetta Code provided an approachable way to:

- Read other people's code.
- Compare multiple implementations of the same problem.
- Practice writing idiomatic Rust.
- Learn GitHub contribution workflows.
- Build confidence contributing to public repositories.

---

# What I Worked On

My contributions focused on solving programming tasks in Rust while gradually improving familiarity with:

- Ownership
- Borrowing
- Pattern matching
- Collections
- Traits
- Iterators
- Error handling
- Standard library usage

Each contribution became an opportunity to compare my solution against more experienced Rust developers and learn better approaches.

---

# Skills Developed

Working through Rosetta Code strengthened several practical skills beyond the language itself.

These included:

- Reading unfamiliar codebases.
- Navigating Git repositories.
- Understanding contribution workflows.
- Writing cleaner Rust.
- Accepting feedback.
- Improving implementation quality through iteration.

---

# Why It Matters

The value of these contributions was not their size.

Their importance lies in developing the habit of learning from existing software instead of working only in isolated personal repositories.

Reading established codebases has since become an important part of how I learn new technologies.

---

# Lessons Learned

Some of the biggest lessons included:

- Simple problems often have many valid solutions.
- Idiomatic Rust is usually simpler than the first implementation.
- Reading existing implementations is an effective learning tool.
- Open source is approachable when broken into small contributions.
- Incremental improvement is more valuable than waiting until something feels "perfect."

---

Long-term, I hope to contribute not only code but also documentation, issue triage and project maintenance.
